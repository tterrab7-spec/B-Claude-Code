DirtBid Build · engineering handoff · October 30, 2026

Adding land feasibility and build operations to DirtBid

DirtBid prices the dirt. DirtBid Build answers what the dirt can become, what approvals it needs, what it's worth, and then runs the job. Everything below is built, tested and pushed. This memo says what it is, how it plugs into DirtBid, and what to do first.

2. Run it

cd dirtbid-build
pnpm install
pnpm --filter @dirtbid/underwriting test
pnpm --filter @dirtbid/parcel-data test
cp apps/api/.env.example apps/api/.env       # DATABASE_URL at minimum
pnpm db:migrate && pnpm db:seed              # Cascade Homes demo portfolio, leads, runs
pnpm dev:api                                 # http://localhost:4000/docs
pnpm dev:web                                 # http://localhost:5173
pnpm --filter @dirtbid/parcel-data live "6000 Godwin Blvd, Suffolk, VA"   # live resolve from the CLI

Or docker compose up from dirtbid-build/ for postgres + api + web.

6. Known limits to be honest about

  • Browser-only mode cannot reach the Census geocoder or the wetlands inventory (no CORS). The resolver falls through to Esri and marks wetlands unknown. Server-side has no gap.
  • Zoning resolves only where a locality layer is configured or a Regrid key is set. Today that is Chesapeake (unverified); Newport News and Richmond endpoints are confirmed and listed in P0.
  • Utilities are always "unknown" from the generic resolver until the locality utility adapters in P0 land.
  • Cost constants are placeholders. The engine is right about structure (Swansboro Place: 91 screened, 90 built); the dollars need Canterbury's data.
  • Geocoders interpolate along the street centerline, so parcel matching uses an envelope and nearest-polygon fallback. A locality address-point layer (Newport News has one) is the precise fix.
